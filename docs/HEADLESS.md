# 独立模式使用教程

独立模式就是：**把 Google 账号导入电脑，之后不用一直开着 AI Studio 网页。** 电脑和反代后台仍要保持运行。目前不支持 Android / Termux 独立模式，手机本地运行请继续用网页模式。

先打开反代终端，选 **3「账号管理与教程」**。第一次可能要下载组件，等网页打开后按下面三步做。

## 第一步：装好助手，点连接

用电脑上的 **Chrome 或 Edge** 登录 AI Studio，再用同一个浏览器打开账号管理页。

第一次需要安装助手，以后不用重复安装：

1. 在账号管理页展开 **「第一次用？安装助手」**，点 **「复制扩展目录」**。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。开启 **开发者模式**，点 **加载已解压的扩展程序**，粘贴刚复制的目录并选择它。
3. 回到账号管理页刷新，点 **「连接浏览器扩展」**，再在弹窗中点 **「连接此管理服务」**。

## 第二步：导入账号，再点启用

1. 只有一个 Google 账号，**账号序号保持 0**。
2. 点 **「导入当前账号」**，等提示导入成功。
3. 在右边或下方的账号列表，找到刚导入的账号，点 **「启用」**。

多个账号：先在 AI Studio 切到要导入的账号。地址里有 `/u/2/` 就填 **2**，有 `/u/1/` 就填 **1**，没有 `/u/` 就填 **0**。每个账号分别导入、启用即可。

## 第三步：回终端，开启独立模式

终端依次选 **4 更多 → 6 执行模式 → 2 独立模式**，然后回主菜单选 **1 启动 / 继续使用**。正在生成时，先结束当前请求。

酒馆里的 **API 地址和密钥都不用改**。本机默认 `http://127.0.0.1:8765/v1`；同 Wi-Fi 手机用终端显示的手机地址。两边默认密钥都是 **`mmdb`**，改过密钥就继续用自己的。

以后日常只要选 **1**，更新选 **2**。多个已启用账号默认先用当前账号，额度不够时换其他可用账号。

## 遇到问题看这里

| 提示 | 怎么做 |
| --- | --- |
| 没检测到助手 | 确认装在当前 Chrome / Edge 配置文件里，刷新账号管理页再检测 |
| 助手未连接 | 点「连接浏览器扩展」，在弹窗中确认 |
| 没有可用账号 | 导入成功后，还要到账号列表点「启用」 |
| 登录过期 | 浏览器重新登录，再导入同一个账号；会更新原账号，不会重复添加 |
| 不想用独立模式了 | 终端选「更多 → 执行模式 → 网页模式」，再在 AI Studio 点 Meow |

**其他导入方式先不用管。** 只有助手用不了时，再展开页面底部的同名选项。

## 准备与导入

在项目目录使用 Node.js 22+ 执行：

```sh
npm run headless -- install
npm run headless -- manage
```

安装器从 AIStudio2API 官方发行页下载固定版本 `v0.2.18`，校验预置 SHA-256 后安装。Windows x64 已实测启动；Linux x64/arm64 和 macOS x64/arm64 提供已固定摘要的安装路径，但本次未实机验证。Android/Termux 当前不支持。系统需有 `tar` 命令。

`manage` 会启动本机运行时，并输出带临时访问令牌的管理链接。使用本机浏览器打开该链接，导入 Cookie JSON、Cookie 请求头、Netscape Cookie 文本或含 `cookies` 的 storage-state 文件。内容只提交到 `127.0.0.1`，由运行时访问 Google 校验账号，不要把凭证发到聊天、截图、日志或代码仓库。

### 一键抓取（Chrome / Edge）

账号管理页提供“验证并导入这个账号”。首次将项目中的 `browser-extension` 目录作为已解压扩展加载到**已登录目标账号的浏览器配置文件**中，再从主菜单 3 打开管理页，点击“连接浏览器扩展”，在扩展窗口核对本机地址并完成连接。详细步骤和权限见[扩展说明](../browser-extension/README.md)。

之后确认 Google 账号序号，点击一次即可读取完整登录 Cookie、提交到本机并验证保存，无需打开开发者工具或发送测试消息。多个 Google 账号共同登录时，序号对应 AI Studio 地址中的 `/u/N/`，默认 `0`。生成中会拒绝导入，完成后再试。

已有账号再次导入会更新凭证。AIStudio2API v0.2.18 的新增接口在验证邮箱后返回 `account_exists`；MMDB 据此定位已有账号，在服务空闲时暂停生成、备份并原子更新凭证，再恢复原运行状态。账号启用开关、代理、额度冷却、资源记录和已有认证扩展字段保留，启动失败会尝试回滚。原文件备份存放在私有目录 `.headless/credential-backups`，同样不要公开或提交到仓库。

扩展只接受已连接管理服务签发的短期一次性请求，Cookie 不显示在页面，不保存在扩展，也不写入日志。连接记录在 `.headless/browser-bridge.json`，管理服务重启后沿用；如需撤销，可在扩展弹窗中断开连接。当前不支持 Firefox、无痕窗口或读取另一个浏览器配置文件。

### 获取 OAuth 续签材料（Windows x64）

在主菜单 3 的账号页展开“从本机 Chrome 导入（含 OAuth 续签）”，填写 Chrome 中已登录的 Google 邮箱，点击“获取 OAuth 并导入”。已有账号可直接点击该账号下的“获取 Chrome OAuth”或“更新 Chrome OAuth”。不需要安装扩展，也不需要发送测试聊天；账号身份、启用开关和冷却记录沿用。

普通扩展的 Cookie 接口拿不到 Chrome 保存的刷新令牌，`chrome.identity` 提供的也是扩展自身的 access token，不能代替本运行时需要的 Chrome OAuth 材料。此入口调用固定版本运行时的 `setup --email`，在私有临时目录读取该邮箱的 Chrome 凭据、换取 Cookie，并核对 Google 返回的邮箱，再更新本机账号。OAuth 材料不传给网页、不写日志，临时文件在操作结束时清理。失败时不会用不完整材料覆盖旧凭证；保存阶段会先备份，并在重启失败时尝试回滚。

目前只支持 **Windows x64 本机 Chrome**；Edge、仅在网页登录、缺少刷新令牌、设备绑定或 Google 要求重新认证时可能无法获取。保存的材料可能依赖原 Windows 设备、用户和 Chrome 配置文件，不能保证复制到 Linux / macOS 后可续签，也不能保证永久有效。其他平台继续使用扩展 Cookie 导入。实现依据：[上游固定版本 setup](https://github.com/Mag1cFall/AIStudio2API/blob/v0.2.18/internal/setup/setup.go)、[Chrome Identity API](https://developer.chrome.com/docs/extensions/reference/api/identity)。

### 手动导入（备用）

尚无凭证文件时，也可从自己已登录的 AI Studio 页面取得：

1. 打开浏览器开发者工具的 **Network / 网络** 页，再在 Playground 发送一次简短测试。这会产生一次真实调用。
2. 找到 AI Studio 生成请求，查看 **Headers / 标头 → Request Headers / 请求标头 → Cookie**，复制 Cookie 的完整值。
3. 回到本地管理页，粘贴到 Cookie 输入框，点击“验证并保存凭证”，账号邮箱由登录会话自动识别。多个 Google 登录账号的序号对应页面 URL 中的 `/u/N/`；没有时使用 `0`。

不要使用 `document.cookie` 代替完整登录凭证，它无法读取 HttpOnly Cookie。这里导入的是 Cookie 登录状态；即使文件带有额外 OAuth 字段，也不代表会导入或保留 OAuth refresh token。若运行时拒绝导入，请重新确认目标账号、Cookie 是否完整和登录是否有效。

也可直接导入本机文件，路径含空格时加引号：

```sh
npm run headless -- import "path/to/cookies.json" 0
```

## 验证与启用

1. 启用需要加入池子的账号，点击“启动生成服务”，刷新到运行中且账号可用。新导入账号需自行启用。
2. 关闭 AI Studio 页面。在本地管理页选择该账号可用的模型，发送固定测试。成功条件是收到完整的 `MMDB_HEADLESS_OK` 和正常完成原因。
3. 退出并重新启动独立运行时，再用同一模型测试，验证凭证可跨进程复用。Windows 可从该运行时托盘菜单退出；仅关闭管理页或执行 `stop` 不会退出进程。
4. 测试成功后执行：

```sh
npm run headless -- enable
npm start
```

`enable` 只改 `config.json` 中的 `executionBackend`，已有 PG 后台需先停止再启动。`npm start` 在 headless 模式下会自动检查并拉起独立运行时。PG 的 OpenAI / Gemini API 地址和本机 API Key 沿用原配置。

项目目录中的 `MMDB.cmd` 已识别独立模式。关闭旧菜单后重新打开即可加载新菜单；原固定安装和 Termux 用户选 2 更新后使用同一套菜单。

| 菜单 | 独立模式下的行为 |
| --- | --- |
| 1 启动 / 继续使用 | 启动 PG 并检查运行时；同时准备本机和局域网入口 |
| 2 更新全部 | 保留配置与凭证，更新后检查后台；不打开油猴安装页 |
| 3 账号管理与教程 | 打开凭证导入、账号池和运行时管理，复用已有管理服务 |
| 更多 → 连接地址与状态 | 查看 PG、运行时、账号就绪情况和两个连接地址 |
| 更多 → 停止后台 | 停止 PG 并暂停守护；运行时、管理入口和凭证保留 |
| 更多 → 浏览器脚本 | 独立模式无需脚本，不打开安装页 |
| 更多 → 执行模式 | 空闲时切换网页 / 独立模式，失败恢复原配置 |
| 更多 → 启动与守护设置 | 开关自动打开网页、进程守护与 Windows 登录自启动 |
| 更多 → 重启后台 | 重新加载 PG 和已打开的管理服务；活动生成会阻止重启 |


更多 → 启动与守护设置 设置进程守护和 Windows 登录自启动；也可直接在独立控制台设置。

更新本地代码后可选「更多 → 重启后台」 加载新后台。已打开的账号管理页需要重新选 **3** 打开新入口；扩展配对仍然保留。PG 原本未运行时，重启操作会按当前后端配置准备本机和手机入口。命令行对应 `node tools/portable-manager.mjs restart`。

主菜单 3 也可以在 PG 停止时使用。运行时尚未安装时，会提示先执行 `npm run headless -- install`。打开管理页不会自动切换 PG 的执行后端，也不会自动发送测试请求。

| 命令 | 作用 |
| --- | --- |
| `npm run headless -- start` | 启动或连接运行时进程，显示状态；无账号时可能为 STOPPED |
| `npm run headless -- run` | 请求启动生成服务 |
| `npm run headless -- status` | 显示生成服务和账号数量状态 |
| `npm run headless -- list` | 列出脱敏账号、启用状态及可用模型 |
| `npm run headless -- manage-url` | 启动或复用后台管理服务，输出本机管理链接；无需保留终端 |
| `npm run headless -- probe <模型ID>` | 发一次固定测试，消耗真实调用 |
| `npm run headless -- stop` | 停止生成服务，保留管理进程及凭证 |
| `npm run headless -- disable` | 将 PG 配置切回浏览器后端，重启 PG 生效 |

停止 PG 只取消它发出的请求，不会终止独立运行时。菜单管理入口的访问令牌保存在私有目录 `.headless/manager.json`；系统重启后重新选 11 会创建新入口。命令行 `manage` 仍为前台模式，需保留终端。不要把管理链接分享给他人，或把管理服务及运行时端口转发到公网。

## 凭证与当前边界

凭证保存在 `.headless/auth`，本机运行时 API Key 和管理密码在 `.headless/control.json`、`.headless/.env`。这些是**受文件权限保护的明文文件，尚未加密**；Windows 限制目录权限为当前用户及 SYSTEM，Unix 使用私有目录。整个 `.headless/` 已被 Git 忽略，发布包使用显式文件白名单，不会打包运行时及凭证。不要把整个项目工作目录直接作为公开压缩包上传。

Cookie 可能过期、被 Google 撤销或要求重新验证；不能承诺永久无人值守。账号页现在显示凭证类型、最近实际验证的时间与来源、最近验证失败原因，并提供“验证登录”。此操作调用固定版本运行时的账号权益 / 模型目录刷新接口，不发送测试聊天；运行时在认证失败时可利用已保存的 Chrome OAuth 材料或可用的本机 Chrome 来源尝试续签。仅保存 Cookie 不代表具备可用的 OAuth 材料；浏览器扩展导入仍只获取 Cookie。

后台仅对已启用、需要登录且已识别续签来源的账号，在生成服务运行、没有逻辑请求时尝试验证。失败间隔至少 10 分钟，连续 3 次失败暂停自动验证；成功验证、重新登录或重新导入会重置失败计数。手动“验证登录”也适用于 Cookie 账号，可以重试；验证成功保留已有额度冷却。认证材料只在本机读取以判断能力，不在页面、公开状态或诊断日志中返回。时间戳来自凭证验证、实际生成或显式账号验证，不把文件修改时间和状态轮询当成登录验证。

账号池错误分别报告 `headless_no_enabled_accounts`（503，无启用账号）、`headless_model_unsupported`（400，模型目录不支持）、`headless_auth_required`（401，需要登录）、`upstream_quota_exhausted`（429，额度冷却）和 `headless_access_denied`（403，访问冷却）。已知冷却期限时，错误 JSON / SSE 带 `retryAt`（毫秒时间戳）与 `retryAfter`（秒）；响应头尚未发送时也提供 `Retry-After`。混合原因或无法确认时使用 `headless_pool_unavailable`（503），不暗示等待即可恢复。

反代与管理器通过操作锁和 `recovery.json` 共享最近检查时间，15 秒内不重复检查；进程内复用管理登录并合并同时进行的只读查询，配置未变化时不重写 `pool.json`。持续 60 秒未就绪、服务空闲且存在非认证失效 / 非冷却账号时，尝试重启生成服务；每小时最多 3 次，重试间隔为 2、4、8 分钟。启动中、活动生成、全部账号需要登录或冷却时不执行这种重启。“立即检查恢复”同样尊重手动停止。恢复仅服务后续请求，不重放已发送的生成。

- 已适配文本及图像输入的流式/非流式、客户端函数工具、工具读取输入、抗截断工具封装与提示词续写。协议转换不支持媒体输出。
- `nativeContinuation: true` 与抗截断请求组合会明确报错；运行时公开 API 不能传递 PG 的原生续写令牌。先在 `config.json` 中关闭该选项。
- 每次实际派发前检查账号状态。多阶段请求若发现启用账号改变，会中止并返回 `headless_account_changed`。测试期间不要在其他管理入口切换账号。
- PG 串行派发并持有跨进程账号租约。池成员与上游当前选中账号独立记录，派发时只启用绑定账号。所有账号不可用时明确返回错误，不循环消耗额度。
- PG 的 `requestCounts` 在此模式下统计发往本机运行时的次数，标记 `requestCountScope: "runtime-dispatch"`。运行时内部仍可能有重试或续写，这不是 Google 实际调用次数。
- 已输出部分内容后发生错误会结束本次请求，不由 PG 自动重放。配额与认证错误采用脱敏错误码，具体账号状态在本机管理页查看。
- `/health` 与 `/v1/status` 返回实际运行时就绪情况；进程存在但未启动生成或无可用账号时，不报告执行器可用。模型特定冷却需在管理页查看。

Camoufox 登录和后台引擎为独立选项；默认轻量后端。首次准备可能需要数分钟，后端切换失败会恢复原配置。登录失败或二次验证由用户处理，凭证失效后不会自动绕过认证。
