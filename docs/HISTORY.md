## 1.7.12：模型目录修正与直接生成

同一页面会话的定时目录刷新不再先清空有效结果，成功解析后再替换。网络或解析失败期间沿用仍在原有 10 分钟有效期内的目录，不因失败延长缓存；上下文变化、断开或显式失效仍立即清除，旧会话结果不能重新启用能力。重复 canonical ID 的关联别名一并禁用，避免通过别名错误启用原生续写。

恢复正常生成直接对 binding 计算摘要、获取 fresh proof 并发送请求，不再查找、读取、填入或清空 Playground 输入框。已有草稿、取消、失败和重试均不影响输入内容。Meow 原生激活、逐次会话验证与上下文变化保护保留。

修复源码检查遇到 HTTP 403 时无法继续更新的问题。Windows、Unix/Termux 固定安装器和便携更新器统一直接下载 GitHub 官方 main 源码 ZIP，从同一份 ZIP 的注释读取完整提交号，不再查询 REST API，也不要求用户配置令牌。每次检查会下载源码包；相同提交跳过重装，同版本不同提交继续更新，配置保留、备份与旧发布包兼容行为不变。

## 1.7.4：默认后台保活、页面响应检测与菜单流程

AI Studio 用户脚本默认建立仅在本机连接的 WebRTC 数据通道，减少后台计时器重度节流和节能模式冻结。连接设置提供“后台保活”开关并保存选择；通道不可用时显示状态，失败后限频重试，关闭页面时释放资源。不播放音频，不申请麦克风或摄像头，不配置 STUN/TURN，不增加 Google 调用。

新版后台向支持的脚本发送应用层心跳，`/v1/status` 区分连接在线和页面响应。页面超过 45 秒未回应一次心跳后，新生成请求明确报 `executor_unresponsive`，已有请求仍遵守原超时和取消机制，不自动重发。旧脚本保留原协议行为。源页恢复、网络恢复及悬浮窗重新获得焦点时检查连接；屏幕常亮仍为独立的可选功能，修复异步申请与释放的状态处理。

后台保活不能阻止操作系统睡眠、浏览器退出、强制丢弃页面或所有移动端后台限制。使用此功能需更新用户脚本并刷新 AI Studio；页面响应检测还需重启新版后台。

统一便携版和固定安装版主菜单编号，将局域网、程序更新和依赖修复放入更多操作。首次使用可直接选 2：自动准备依赖和后台，确认当前版本脚本可访问后打开安装页；日常选 1 启动。脚本更新沿用已运行的后台及模式，不中断生成；停止或更新程序前检查活动请求。结果页按回车返回，并明确区分程序更新、脚本安装和刷新 AI Studio 三个步骤。

本次通过 248 项 Node 回归、Windows 固定管理器集成测试与发布包解包启动检查；菜单测试覆盖缺少依赖、未启动后台、已有请求、脚本不可用及模式保留。真实 Chrome 已验证本机数据通道建立、关闭及重新启用，检查了面板显示。自动化验证页未呈现真正隐藏状态，尚未验证真实 AI Studio 长时间后台运行或强制冻结后的表现；Unix 菜单通过语法检查，Linux / Termux 真机流程仍未验证。

## 1.6.0：按额度切换账号

账号识别进一步改为手动确认的主邮箱。不同邮箱复用同一 Google 账号位不再混用冷却，同一邮箱跨浏览器仍共用冷却并限制重复连接。面板记录最近使用的邮箱作为候选，新页面或账号上下文变化后重新确认；邮箱与各模型冷却保存在本机 accounts.json，重启与固定管理器更新后保留。公开健康接口及诊断文件不记录邮箱，页面日志只显示掩码。旧脚本保留账号位兼容，需更新后才能使用邮箱识别。

将最初的轮询与按队列负载分配调整为持续使用当前账号。并发请求继续在当前页面排队，额度受限后才使用已连接的备用账号；旧账号冷却结束、新账号接入都不会主动抢回请求。日常可只保持一个账号在线，用完后手动换号、发送 hi、确认邮箱，再重新发起请求，无需预先登录全部账号。

Google HTTP 429 与 RPC code 8 均记录当前账号、当前模型的冷却，默认 15 分钟，可通过 accountCooldownMs 调整。HTTP 429 只在初始请求尚无上游数据时自动转交备用账号；RPC code 8 保留本次错误，在下次请求选择可用账号。已有输出、输入读取已完成或续写中的请求不跨账号重放；保留原请求总时限与取消行为。

面板日志区分当前和备用页面，/v1/status 增加账号策略与 active 状态。无备用时提示手动切换步骤。本版不读取 Google 密码、不内置自动登录浏览器，.env 文件加入 Git 忽略规则。使用步骤和账号位识别边界见[账号使用与切换](USAGE.md#账号使用与切换)。

## 1.2.11：请求鉴权修正与断联诊断

- 每次请求重新计算能够从当前页面 Cookie 读取并明确识别的 SAPISID 签名段，不再始终重放上次发 hi 捕获的时间戳。读不到 Cookie 或遇到未知扩展格式时保留页面原值，不丢弃其他账号或会员请求头。
- 不再重放上次页面生成请求的 `x-goog-ext-*` 动态上下文头。保留页面真实的 API 标识、会员档位、账号选择与 visit-id。
- Google 连接失败时记录页面可见性、浏览器在线标志、页面定时器最长间隔和是否刷新签名；在菜单 `3` 可看到这些状态。不记录 Cookie、签名或聊天正文。
- 继续区分 Google 上游失败与本地 WebSocket 断开。没有增加重复生成、放宽安全检查或继续延长超时。

这些是已验证的请求处理修正，**尚未通过真实 4A 长请求证明能消除断联或缩短生成时间**。日志里的在线标志不等于 Google 一定可达，定时器长间隔也可能来自后台节流、忙碌或系统休眠，不能单独当作根因证明。此次没有修改抗截断工具或尾部提示词。
