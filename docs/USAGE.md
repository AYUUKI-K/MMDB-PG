# 喵喵电波 · MMDB 本地反代

适用于 **1.18.0**。以下文件与命令均相对安装根目录；首次安装与平台选择见[安装说明](INSTALLATION.md)，源码入口见[主说明](../README.md)。

日常打开原来的菜单，选 **1**；更新选 **2**，在油猴确认后刷新 AI Studio；首次或仅修复脚本选 **3**。结果页按回车返回，退出菜单不会停止后台，结束生成后选 **6** 才会停止。版本与地址看 **4**。菜单顶部是文件版本，状态页中的后台与浏览器脚本版本可能不同，应分别核对。

选 1 或局域网启动时，菜单先检查浏览器连接，约 3 秒后仍无连接才尝试打开 Playground。Windows 使用默认浏览器，Termux 优先使用 termux-open-url；没有自动打开时，把地址复制到装有油猴的浏览器。已有脚本无需每天重装，新会话仍需登录和 Meow 激活。查看状态和命令行诊断不会自动打开网页。

## 账号使用与切换

每次连接一个 AI Studio 页面，所有请求在该页面执行。

1. 在 AI Studio Playground 登录账号，安装本地提供的用户脚本，点击一键激活。面板在当前标签页新建对话并发送 Meow，会话就绪后直接连接本地服务。
2. 需要更换账号时，结束当前生成并关闭旧页面，再登录或打开另一个账号的 Playground。
3. 在新页面点击一键激活，等面板显示连接成功，再回到酒馆重新发起请求。

如果原页面仍连接，其他页面会提示先关闭原页面，再点击重连。页面断开时，在途请求会失败；重新连接后只处理新发起的请求。

1.7.3 移除了邮箱读取、填写和记录、额度换号提醒、模型冷却及备用账号自动切换。Google HTTP 429 或 RPC code 8 作为上游错误直接返回，不因额度错误自动重试，也不拦截下一次手动请求。单纯本地连接中断后可自动重连；原生请求上下文变化时会停止旧请求并重新连接当前会话。

升级后请同步更新用户脚本并刷新 AI Studio。新版脚本会清除旧版浏览器邮箱候选记录；后台不再读取或写入 accounts.json，旧文件可自行删除，也不需要迁移。旧配置中的 accountCooldownMs 被忽略。

Google 账号由你在浏览器中登录，MMDB 不读取或保存 Google 密码。

Windows / Linux / Android Termux 共用此包，需要 Node.js 22+。默认密钥 `mmdb`，只支持文本聊天。浏览器需支持用户脚本；后端不能代替已登录的 AI Studio 页面。

## PG 自动读取输入

在 MMDB 浏览器面板的“生成设置”中开启**工具读取输入**。设置自动保存，后续请求立即生效。酒馆沿用原来的 PG 地址和模型，在普通输入框输入并发送即可。若使用了其他输入读取扩展，应关闭重复功能。这个开关不要求酒馆开启 Function Calling。

默认读取模式下，PG 会先发起一次真实的 `mmdb_read_input` 模型调用，校验返回的请求编号，再将本轮原文作为相应的工具结果提供给第二次生成。上游返回的工具调用 ID、思考签名随对应调用保留。客户端只收到最终正文，中间读取过程不写进酒馆聊天记录。普通模型和抗截断模型均支持。

当前范围是请求中**最后一条 user 消息的文本**，不是全部预设、世界书或历史。若酒馆预设把尾部指令也发送成 user 消息，读取对象就是实际请求里的最后一条 user；PG 无法仅凭兼容接口判断哪一段来自输入框。历史、系统提示及角色上下文在生成阶段保留。图片和附件仍未实现。

带外部函数声明或工具历史的请求使用下文的通用工具接口，本轮跳过内置读取、抗截断和自动续写；保存的开关偏好不变。普通文本请求仍按原设置执行。

新安装默认关闭，可随时关闭恢复原流程。真实读取模式每轮增加一次模型请求及其用量，首个正文通常会更晚到达；读取阶段最多请求 1024 输出 token，不占用正文的输出预算。编号不匹配、未调用读取工具、拒绝、超时或断流会明确报错，不会伪造读取成功。读取与正文两阶段共用整次请求期限，并支持酒馆停止按钮取消。

2026-10-25 已实测 Argon 普通接口及 SillyTavern 1.19.0 中的 Argon 抗截断请求，两者均完成输入读取和正文交付，诊断确认 `inputReadCompleted: true`、`inputReadCalls: 1`。其他模型、长角色卡及原生跨轮长输出仍需各自验证。

### 合成读取记录

**合成读取记录**是正式的可选省请求功能，默认关闭。先开启“工具读取输入”，再打开此开关。本地为最后一条 user 文本构造配对的读取调用与工具结果，使用固定占位思考签名，直接请求正文；在没有续写时，将两阶段的 2 次上游生成减为 1 次。普通模型、抗截断模型、提示续写及原生续写沿用各自输出流程。

2026-10-28，使用者在真实 PG 链路完成了开关对照：开启合成读取后正常交付正文，面板记录上游 1 次（读取 0 / 正文 1 / 续写 0 / 重试 0）；使用者报告关闭合成读取后，同样的一般生成流程为 2 次请求。由此确认该链路可以省去读取阶段；无续写和重试时，基础请求次数减少 50%。该反馈没有提供模型标识，不据此宣称所有模型均已验证。

遇到不兼容模型时可关闭合成读取，改用原有真实读取模式。签名拒绝、HTTP 错误或断流会明确报错，不自动补发两阶段请求或重试，以免增加消耗。关闭“工具读取输入”时，合成选项不生效，但保存的偏好保留。

合成历史不被记为模型真实调用：诊断 `inputReadMode: synthetic`、`inputReadCalls: 0`、`inputReadCompleted: false`；真实模式为 `real`，关闭为 `off`。两种模式都只包装当前请求的最后一条 user 文本，不共享输入、调用 ID 或真实思考签名。

### 查看实际请求次数

面板显示 **本轮上游 N 次 · 启动累计 M 次**。“已送达”仍统计成功回复数。最近活动在成功、失败或取消时显示本轮的读取、正文、续写、重试次数。后台重启会清零累计；页面刷新或重连会重新获取后台累计。最近 50 条请求的计数随现有诊断历史保留。

计数来自浏览器发起 Google GenerateContent 时的通知；重复进度不重复计数，排队、准备和会话验证不计。失败请求、网络重试和续写会计入。后台能力探测单独计入累计的 `probe`，不增加已送达数；Meow 激活、网页手动生成、模型列表和其他程序的请求不在统计范围内。它是本后台观测的请求尝试次数，不是 Google 官方扣额或剩余额度，连接中断时上游是否收到请求仍无法确认。

`GET /v1/status` 返回 `requestTotals`（含 `startedAt`、`total`、`inputRead`、`answer`、`continuation`、`retry`、`probe`）。每条 `active` / `recent` 记录含 `requestCounts`（不含 `probe`）。OpenAI JSON 响应的 `mmdb.requestCounts` 和 SSE 最终完成块的同名字段也提供本轮计数。旧历史没有计数时不补成零；旧执行器未报告的失败尝试无法追溯。

## 反代面板

面板上方显示会话与本地连接状态，生成时显示当前阶段和耗时；下方提供输入读取、合成读取记录和原生续写开关。密钥与复制 API 地址位于“连接设置”。“最近活动”保留最近 40 条关键记录，可随时清空，用量仅显示上游实际返回的计数。

**一键激活 · Meow**：点击后通过 AI Studio 原生按钮在当前标签页新建对话，再发送 `Meow`；已是空白新对话时直接使用。等待会话捕获和页面结束生成后，自动连接本地服务。不会自动清除已有草稿；酒馆或 AI Studio 正在生成时拒绝激活；重复点击不会重复发送。新建失败、页面加载中、控件不可用或发送后等待超过 60 秒会显示提示，不自动重发。也可以自行在页面发送任意简短问候完成激活。

**悬浮窗**：支持 Document Picture-in-Picture 的浏览器把同一个实时面板移到置顶窗，切到酒馆标签页或其他应用仍可查看状态、修改设置。桌面浏览器不支持时打开普通小窗，普通小窗不会自动置顶；置顶请求被拒绝时可点击“改用独立小窗”。手机缺少置顶能力或申请失败时保留页内状态条，具体见下方手机说明。关闭独立小窗或点击“收回面板”会恢复原页面上的面板，开关、日志和输入内容保留。AI Studio 源页面必须保持打开，关闭或刷新源页面会结束该窗口。浏览器能力说明见 [Chrome 官方文档](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)。

**后台保活**：默认随 AI Studio 用户脚本启用，无需每次点击。可在“连接设置”中关闭，选择保存在当前脚本管理器中。状态为“后台保活运行中”才表示通道已经建立；不支持或启动失败会明确提示，并在失败后限频重试。它建立本机 WebRTC 数据通道，不配置 STUN/TURN 服务，不采集音视频、不播放声音、不增加 Google 请求；会占用少量额外资源。Chrome 对开放数据通道的后台任务有[计时器节流例外](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)和[节能冻结例外](https://developer.chrome.com/blog/freezing-on-energy-saver)，其他浏览器行为可能不同。

底部“常亮”仅用于防止屏幕熄灭，仍需自行开启；它与后台保活互相独立，页面隐藏时可能被浏览器释放。后台保活不能防止电脑休眠、浏览器退出、强制丢弃页面或所有手机后台限制。源页面仍需保持打开；若保活不可用，可让 AI Studio 独立窗口保持可见。

**跟随酒馆美化**：底部配色默认选择“跟随酒馆”。同一浏览器配置、同一个脚本管理器中，酒馆页和 AI Studio 页启用同一份 MMDB 脚本后，会自动同步酒馆实际生效的背景、文字、强调色、边框、字体栈、圆角和阴影。换主题后约 1.5 秒内更新，面板与悬浮窗共用最新外观；关闭酒馆后保留最后一次主题。每位用户读取自己的主题，不共享其他人的配色。

更新脚本后需打开或刷新一次酒馆页面。默认覆盖 localhost、127.0.0.1 与常见私网 IPv4 地址的任意端口；使用自定义域名或 IPv6 时，在油猴的脚本设置中为酒馆地址添加“用户匹配”规则，再刷新酒馆。不同浏览器或配置之间不共享用户脚本存储，需要在运行 AI Studio 的同一浏览器中打开酒馆。未读到主题时使用中性默认配色；底部也可切换固定浅色、深色。

同步的是可移植的样式值，不加载整份自定义 CSS，也不复制背景图片、远程字体文件或依赖酒馆 DOM 的装饰。字体会使用该浏览器中可用的同名字体，否则沿字体栈回退。样式通过脚本管理器本地存储传递，不发送到 Google 或本地反代 API。

### 安卓画中画

手机默认显示可拖动的小状态条，点击展开。支持视频画中画的安卓浏览器会显示 **画中画 ↗**：点击后打开系统小窗，再切到酒馆或桌面。小窗是本机生成的静音状态视频，显示连接、生成状态、耗时和送达次数；不包含正文、密钥，也不申请摄像头、麦克风或录屏权限。设置与操作仍在原页面，点击“关闭画中画”或系统关闭按钮结束小窗并释放视频资源。

画中画采用本地 Canvas 首帧 → 1fps 视频流 → 等待元数据 → 播放成功 → 标准 PiP 申请的顺序。视频是本项目绘制的状态画面，包含连接状态、耗时、送达次数和时钟；不加载远程视频，也不显示会话正文或密钥。关闭系统小窗会同步恢复按钮并释放视频轨道与定时器；加载、播放与申请均有超时，避免按钮一直显示“正在打开”。

修正 1.7.15 的过严检测：浏览器没有提供 `pictureInPictureEnabled` 标志、但提供了 `requestPictureInPicture()` 时，仍允许申请；明确返回 `false` 或缺少调用方法时，会显示实际原因。桌面优先保留完整 Document PiP 面板，其他提供标准视频 PiP 的浏览器使用本地视频；不能仅凭 Chrome、Edge、Firefox、Safari、Via 等名称判断支持情况。

安卓需要在系统设置中允许当前浏览器使用画中画。Termux 只运行后台，不提供浏览器画中画能力。Via / WebView 如果缺少标准调用接口，这种方式与参考脚本一样无法强制开启原生 PiP；“缺少接口”和“申请被拒绝”是不同问题，打开系统权限不能补出缺失接口。此时可以继续使用页内面板和现有后台保活。不会使用全屏视频或整页新标签假装画中画成功。接口说明见 [MDN 视频画中画](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestPictureInPicture)。

画中画需要保留 AI Studio 源页面，刷新或关闭源页面会结束小窗。它可以帮助维持前台媒体活动，但不能保证抵抗安卓省电、浏览器冻结、系统杀进程或 Google 上游网络错误。安卓还需为 Termux 和浏览器关闭过严的电池限制。

标题与小状态条也支持方向键移动，Escape 可收起设置或面板，浅色和深色可在底部切换。

## 安装浏览器脚本

菜单选 3，或在后台运行时打开 `http://127.0.0.1:8765/local-pg.user.js`，将 **MMDB 本地桥**原位更新到 **1.18.0**，然后刷新 AI Studio。自定义端口以菜单 4 输出为准；只更新程序文件不会自动更新已经运行的浏览器脚本。

进入 AI Studio Playground，点击一键激活，确认面板显示本地已连接、Google 已就绪。激活前需自行处理输入框中的草稿；激活后的反代生成不会读取或修改输入框。

酒馆使用聊天补全 → 自定义兼容 OpenAI：

- 本机 Base URL：`http://127.0.0.1:8765/v1`
- 密钥：`mmdb`
- 普通模型：如 `pg-gemini-4-argon`，支持流式显示。
- 抗截断模型：如 `pg-gemini-4-argon-抗截断`，通过正文工具交付，按完整工具参数返回；实测正文一次显示。

普通与抗截断使用同一登录账号。工具模式不是更高额度，也不能保证消除所有截断。没有实际调用正文工具时明确报错，不静默切回普通输出。上游断流、额度和拒绝保留为错误。酒馆点停止会取消请求。

### 直接生成与 Playground 输入框

1.7.12 恢复直接生成：执行器在内存中对请求的 binding 计算 SHA-256，每次获取页面的会话验证，再通过请求接口发送结构化上下文。普通文本请求的绑定串包含各轮 user / assistant 文本，不包含单独的 systemInstruction；系统提示仍通过请求体的独立字段发送。正常生成不读取、填入或清空 Playground 输入框，不点击 Run 按钮，已有草稿及生成中输入的文字会原样保留。取消、失败与允许的网络重试也不修改输入框，已激活的会话不依赖输入框是否渲染。

Meow 激活仍通过原生输入框和 Run 按钮发送简短消息，用来捕获真实页面会话；激活期间拒绝反代生成。保留逐次会话验证、空验证串的原生证据检查、上下文变化保护和取消流程。历史 1.2.12 曾移除输入同步，1.5.0 独立代码线合入时恢复，1.7.12 再次将正常生成与输入框分离。

## 局域网

LAN 启动方式会同时启动本机核心和手机 API 网关。唯一可识别的私网 IPv4 会自动生成 lan-config.json；多网卡、VPN 或地址变化时，参考 lan-config.example.json 手工修改 address 与 allowedCIDR。

手机填启动窗口显示的 `http://电脑局域网IP:8766/v1`，密钥与电脑一致。电脑与手机应在可互通网络中；如系统防火墙提示，允许家庭私网访问。LAN 只提供生成 API，限制配置网段并验证密钥。不要把此入口映射到公网。

电脑仍运行后台与已激活的 AI Studio 页面；手机只调用 API 时不需要再装本项目用户脚本。手机的 127.0.0.1 指手机自己。推荐先选 6 停止旧模式，再选 7；详细步骤见[手机连接电脑](INSTALLATION.md#手机连接电脑)。

## 配置与等待

首次生成 config.json，已有配置保留。默认值：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| port | 8765 | 本机端口 |
| apiKey | mmdb | 个人密钥 |
| timeoutMs | 600000 | 普通模型首个有效内容／已有正文后的数据空闲上限，毫秒（10 分钟） |
| toolFirstByteTimeoutMs | 600000 | 工具模式首个有效工具正文等待上限，毫秒；JSON 前缀和思考帧不缩短此预算 |
| queueTimeoutMs | 120000 | 新版浏览器执行器开始工作前的排队上限，毫秒 |
| maxRequestMs | 1800000 | 整次请求总时长上限，毫秒；含排队、重试和所有续写 |
| streamKeepAliveMs | 15000 | SSE 注释／非流式 JSON 空白保活间隔，毫秒 |
| maxContinuations | 2 | 最多额外续写次数，可设 0–5；提示词续写需明确 MAX_TOKENS、已有正文且未耗尽请求输出预算 |
| nativeContinuation | false | PG 原生续写；仅对具备已确认能力的抗截断模型启用 |
| inputRead | false | 启用工具读取最后一条 user 文本，默认采用真实两阶段模式 |
| inputReadSynthetic | false | 仅在 inputRead 开启时生效；合成读取历史，省去一次读取请求；关闭后使用真实读取模式 |
| models | 内置模型列表 | 固定保留的模型条目；有效页面目录还会追加普通文本模型 |

已有安装更新后会保留 config.json 中的值。若 timeoutMs 仍为 180000（3 分钟），将其改为 600000（10 分钟）并重启后台即可延长等待。

SSE 注释没有正文，不会延长上游等待期限。非流式响应每隔同样的时间发送合法 JSON 空白，最后仍是一个完整 JSON 对象；保活不含正文。保活发出后 HTTP 状态已为 200，晚到错误通过 JSON error 对象返回；首个保活之前的错误仍使用实际 HTTP 状态码。未实际收到上游数据时，本地代码无法提前显示正文。

## 计时和诊断

面板“请求耗时”包含执行器排队，完成时使用后台从收到该次生成请求起计算的总耗时。它不包含酒馆发起请求之前的预处理，也不等于酒馆的“思考”标签或页面渲染耗时。酒馆使用近似分钟显示时，152 秒可能显示为“3 分钟”；可悬停其标签查看秒数（取决于酒馆版本）。

`GET /v1/status` 需要 `Authorization: Bearer mmdb`，包含活动请求及最近 50 次调用的阶段、数据块数与相对耗时。firstClientTextMs 表示后台第一次调用正文写出，不是酒馆收到或显示的时刻。诊断仅保存元数据到 diagnostics.log，不保存提示词、正文、Cookie 或令牌。

1.7.4 的 `page` 字段包含页面响应状态（checking、responsive、unresponsive、unsupported、offline）、上次响应距今毫秒数、心跳往返耗时、页面可见性和保活状态。后台每 15 秒检查，最多保留一个待回应心跳；45 秒未回应视为页面暂不可用，新请求提示 `executor_unresponsive`。WebSocket 自动 pong 不能代替页面 JavaScript 的回应。该检测不主动中止或重复生成，也不延长已有请求期限。旧脚本显示 unsupported，需同时更新后台与用户脚本才能使用此检测。

工具读取增加 `inputReadEnabled`、`inputReadCompleted`、`inputReadCalls`，尝试记录用 `reason: input-read` 区分读取阶段。用量包含读取请求；缺失的上游计数仍保持未知。设置接口 `POST /v1/experiments` 接受局部更新，例如 `{"inputRead":true}`，不会覆盖其他功能开关。

## 响应前连接失败的恢复

仅提示词续写的抗截断模式在收到任何响应字节之前发生连接错误（包括已有响应头但读不到数据），会重新生成会话验证并自动重试一次。同一个客户端请求最多一次恢复，包括后续 MAX_TOKENS 轮次；整体等待上限不因重试而重置。已收到任何响应字节后的断流、任何 HTTP 错误、额度、权限、内容拒绝及主动取消都不重试。原生续写模式不重试传输失败，避免重复消费状态不明的续写凭据。

断开时无法确认 Google 是否已开始生成，因此重试可能额外消耗一次调用；它不能保证网络不掉线。面板会明确显示重试事件，诊断 networkRetries 记录次数。普通模型不启用这层恢复。

## 用户脚本自动更新

## 性能诊断与精简策略

本版记录实际发送的 generation 参数、toolPromptStyle、每次请求尝试的阶段时间和上游用量。usage 中缺失的 token 字段表示未知，显式 0 才是报告为零。usageComplete 表示能否完整汇总输入、输出、思考和总 token 计数；失败尝试的未报告用量不会被假装为零。attempts 中分别保留首次尝试、网络恢复和续写的数据，单次使用上游累计计数的最后值，不重复相加每个响应帧。HTTP 兼容接口与诊断共用同一份记录：无法得到完整 OpenAI 用量统计时省略 usage；诊断仍保留上游明确报告的部分计数。原生续写的输入不重复相加，其总量还依赖前轮工具 token 计数，缺失时保持未知。

面板区分响应头、响应数据和正文到达；这些时刻都不能精确表示 Google 内部开始或结束思考的时间。

精简交付要求已作为可选方案实现：在 config.json 中添加 `"toolPromptStyle": "compact"` 后重启后台即可启用；恢复 `"legacy"` 可回退。两种策略的模型、温度、topP、输出上限和思考设置完全一致，精简版只减少重复交付指令，仍保留真正的工具声明、user 结尾和严格工具结果验证。模型列表不增加第三类。

默认使用 legacy。精简策略已通过离线结构和回归检查，实际工具调用成功率与性能仍需实测。网页 Run settings 不会自动同步到反代，未显式发送的生成参数在诊断中记为 provider-default；thinkingConfigSent=false 表示没有发送思考配置，不表示模型没有思考。

在项目目录运行 `node tools/performance-report.mjs` 可只读汇总现有诊断，无需生成请求。仅统计有明确配置、没有重试／续写的成功记录，按普通／工具策略分组显示中位数和可用的 token 统计；未知计数显示 null，旧记录缺少配置会被排除。输入不同的自然使用记录仅供趋势参考。

## 长时间非流式请求

反代给非流式请求发送 JSON 空白保活。酒馆原本会把整篇 JSON 缓冲完再回复浏览器，因此使用酒馆时还需在酒馆所在设备运行一次：

```sh
node tools/install-st-keepalive.mjs "你的SillyTavern目录"
```

然后重启酒馆。Windows、Linux、Termux 都可用同一命令；手机酒馆装在手机上时，补丁也要应用在手机酒馆目录。命令会检查生成入口的结构，不匹配时拒绝修改，重复运行不会叠加补丁。酒馆更新后若覆盖了补丁，重新运行即可。只转发带 MMDB 标记的自定义 pg- 模型非流式 JSON，不修改预设、聊天、普通流式显示或其他提供商的行为。

这段保活让本地 HTTP 链路不再长时间完全静默，无法取消客户端自己的固定总时长上限，也无法向 Google 的响应连接注入数据。如果依然在固定时间断开，需要结合该客户端的限制继续定位。诊断 clientKeepAlives / lastKeepAliveMs 记录保活发送情况；client_disconnected 表示调用方断开，不能单凭该状态认定是超时。

Google 连接失败只在没有收到任何数据时允许已有的一次恢复；读到部分内容后断流会明确报 upstream_stream_disconnected，不重放已收到的内容、不伪装完成，也不无限重试。代理或 Google 主动断线仍可能失败；本地保活不能保证修复这一段网络。

## 交付正确性与原生续写

LAN 网关现在保留 MMDB 的 JSON 空白保活标记，使电脑核心 → LAN → 酒馆后端 → 客户端的非流式保活完整传递。酒馆端仍需安装上文的保活适配。工具生成错误、未知完成枚举、空白工具正文、工具与普通正文混合输出都会明确失败；流式已交付的部分内容不能收回，但不会追加成功结束信号。收到 finish 帧后仍等待整个上游传输正常结束，并接收尾随的 usage 帧。

架构仍是酒馆 → 可选 LAN 入口 → 本机 Node 核心 → 浏览器执行器 → PG。核心新增独立的 `deadlines.mjs` 和 `capabilities.mjs`；续写由 `continuation.mjs` 负责，用量由 `metrics.mjs` 统一汇总。新版浏览器协议区分连接、逻辑请求、轮次请求和网络尝试，忽略迟到的旧尝试数据。排队取消不会继续执行；账号请求上下文变化会取消旧任务并清空旧目录。旧脚本可以继续使用基础交付，但不启用原生续写，也没有新版独立排队计时，应与后台一起升级。

浏览器通过当前页面捕获到的实际请求头查询 ListModels，不伪造会员或账号信息，不读取聊天内容。目录只保留在当前连接内，定期刷新，10 分钟过期；`/v1/status` 的 catalog 显示状态与已配置模型的能力。1.7.9 起，`/v1/models` 与 `/v1beta/models` 在配置列表之外追加当前目录确认的普通文本模型，排除媒体 / 实时专用模型、别名和冲突条目。目录过期、失效或页面断开时回退到配置列表。配置中的普通与抗截断条目保留，新发现的模型只增加普通条目，不自动添加抗截断变体。

原生续写默认关闭，可在面板“生成设置”中开启；手动修改 config.json 的 `"nativeContinuation": true` 后需重启后台。后台与用户脚本应使用配套版本，模型能力目录需同时声明函数工具、output_continuation 和有效 token 上限。实际使用方式记录在诊断 `continuationMode` 中：native / prompt / none。开关开启但能力不满足时，继续使用提示词续写；一旦已经进入原生流程，协议错误不会静默切换为提示词重放。

原生流程保持原始 contents、system、工具声明和 WAA binding，逐轮生成新的 proof，只追加 PG 返回的 continuation token；每轮累计输出上限增加 32768，受 max_tokens、maxContinuations 和 maxRequestMs 共同约束。明确 CONTINUATION，或带本帧 token 且仍有输出预算的 MAX_TOKENS，才会触发下一轮。缺失／重复 token 或必须续写但预算耗尽时明确报错；正常 MAX_TOKENS 没有可用续写条件时仍报告 length。凭据不会写进诊断日志或客户端响应。

模型能力的实测范围见 [EXPERIMENTS.md](EXPERIMENTS.md)。工具参数按完整 protobuf 对象解码；原生续写仍受模型能力、输出预算和上游连接状态限制。

## 续写接缝、输出预算与工具校验

提示词续写轮的正文先暂存到该轮上游传输正常结束，再检查与已有正文的接缝。至少 32 个 UTF-16 单元、包含至少 16 个字母或数字的精确重叠才会移除；通常比较末尾 8192 个单元，也识别整篇原文的完整重放。短句、标点、空行和代码围栏不做模糊去重，正文不会被统一空白或改写。若整轮只重复上一轮／已有正文，或移除接缝后没有新增正文，返回 `continuation_no_progress`，停止额外请求。流式已显示的前轮内容保留，重复的续写正文不会再发出，也不会追加成功结束信号。首轮和原生续写的交付时机保持原有行为。

**输出上限语义调整：** 提示词续写现在将显式 `max_completion_tokens`、`max_tokens` 或 Gemini `maxOutputTokens` 视为整次答复的预算，后续轮次扣除各次尝试已报告的输出与思考 token，不再每轮重置。`max_completion_tokens` 优先于 `max_tokens`。预算耗尽、或缺少准确计数无法确定剩余额度时，不再自动续写，保留 `length` 结束原因；未设置输出上限时仍使用上游默认值，并受续写次数和总时长限制。需要长答复时，应在酒馆设置足够的输出上限。预算不会用字符数估算 token，也不能约束上游误报用量或响应前网络重试的未知消耗。

正文工具允许先到名称、后到参数；带调用 ID 时，同一答复内的 ID 必须一致。同一帧多次调用、调用 ID 切换、完成后继续调用，以及尚未验证的参数扩展均明确失败，不把不同调用或未解析参数拼成正文。原生续写仍默认关闭，没有尝试向 PG 注入未经验证的 `ANY` 或 `streamFunctionCallArguments` 字段。

诊断记录 `continuationOverlapChars`（移除的重叠长度）、`continuationRemainingTokens`（已知的剩余预算）和 `continuationStop`（`output_budget` / `unknown_usage` / `max_rounds`），不保存正文、调用 ID 或签名。离线回归覆盖接缝、重放、预算、工具标识及断流；真实模型的工具增量参数与长输出需单独验证。

升级后重启本地后台，更新用户脚本并刷新 AI Studio。现有配置无需增加字段。

## 客户端工具接口

1.18.0 开放通用 function 工具接口，不需要额外配置开关。客户端在 `/v1/chat/completions` 请求中提供 `tools`，接收 assistant 的 `tool_calls` 后自行执行函数，再把原 assistant 消息与对应 `role: tool` 结果一起发送下一轮。调用 ID 必须匹配；调用参数必须是 JSON 对象字符串，一组并行调用的结果全部返回后才能继续普通聊天。

支持 `tool_choice: auto`（有工具时默认）、`none`、`required` 与 `{ "type": "function", "function": { "name": "工具名" } }`。`none` 不发送新的可调用声明，但可携带已经完成的历史。`required` 和指定函数通过声明筛选、生成指令加返回校验实现；模型未遵守会报错，不伪造成功。`parallel_tool_calls: false` 会在返回前拒绝模型违规生成的多个调用。

最小声明示例：

```json
{
  "model": "pg-gemini-4-argon",
  "messages": [{"role": "user", "content": "查询上海天气"}],
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查询城市天气",
      "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]
      }
    }
  }],
  "tool_choice": "auto"
}
```

反代不运行 `get_weather`，也不访问工具指定的地址。工具的执行权限与结果由客户端负责。声明和工具结果占用上下文，工具循环可能增加请求次数、延迟和 token 用量。不携带工具声明或历史的请求保持原流程。

工具请求即使选择了 `-抗截断` 模型，也使用同一基础模型的普通工具流程：本轮不追加 `mmdb_emit_answer`，不执行内置读取、自动续写或网络重发。OpenAI 响应的 `mmdb.externalTools`、`inputReadSkipped`、`antiTruncationSkipped` 说明这一行为；`inputReadMode` 为 `external`。普通聊天仍按保存的生成设置执行。

JSON 与 SSE 都保留完整工具参数、调用 ID 和调用上的 `extra_content.google.thought_signature`；客户端须把该扩展字段随 assistant 历史原样回传。缺失签名的历史采用已有占位签名机制，目标模型是否接受仍取决于上游。SSE 正文可以实时输出，工具调用会等上游正常 STOP、参数完整后一次性交付；结束原因为 `tool_calls`。工具调用出现截断、参数冲突、未知函数或异常完成状态时，返回错误，不交付可执行的部分参数。

Gemini 入口支持 `tools[].functionDeclarations`、`toolConfig.functionCallingConfig`（AUTO/NONE/ANY，ANY 可带 allowedFunctionNames）以及带 ID 的 `functionCall`/`functionResponse`。当前仅支持函数工具和文本结果，不支持 Google 内建搜索/代码执行工具、旧式 `functions`、非函数工具或 `strict: true`。参数 Schema 支持明确的对象、数组、字符串、数值、整数、布尔类型，嵌套 properties/items、required、字符串 enum、nullable 和常见长度/数量/数值范围。`additionalProperties` 布尔约束附加到声明说明，不承诺严格执行；引用、联合类型及其他未支持约束返回 400。

验证覆盖本地模拟执行器的声明、JSON/SSE、工具往返、并行调用与错误分支；真实 Google 模型的调用选择及参数格式仍可能有差异。

## 静音音频保活

更新油猴里的 **MMDB 本地桥 1.18.0** 并刷新 AI Studio，在面板“连接设置”开启“静音音频保活”。它默认关闭，独立于默认开启的 WebRTC“后台保活”，可同时使用。只在浏览器内循环播放零采样、零增益音频，不下载媒体、不启用麦克风、不产生 Google 请求。

首次开启通过点击启动；保存的开启偏好在页面刷新后等待一次交互。浏览器暂停或阻止播放时，面板显示“等待点击启动”并提供恢复按钮；关闭开关或退出页面会释放音频资源。音频上下文可能增加少量资源和耗电，实际后台效果由浏览器及系统决定。

Chrome 不把静音音轨计入有声音频的后台限流豁免，因此“播放中”仅代表音频上下文正在运行，不代表页面不会休眠。保留 WebRTC 保活；手机系统冻结、设备休眠仍需用户自行处理。

## 菜单连接状态

一键菜单标题下显示“反代 运行中 · 本机/局域网”和“浏览器脚本 已连接/未连接”。每次进入或返回菜单重新查询，等待输入时不持续刷新。绿色表示已确认运行或连接，黄色提示未运行、未连接、页面暂未响应、活动请求或需要更新的版本。

状态读取先核对本目录 PID 与进程脚本路径，再查询本机接口，HTTP 请求有 3 秒时限。旧后台、端口/密钥不匹配或无法确认时提示选 4 检查，不把其他目录服务误报为本目录。读取状态不会启动后台、修改配置或调用 Google。
