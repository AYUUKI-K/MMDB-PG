# 喵喵电波 · MMDB 本地反代

以下文件与命令均相对安装根目录；开发入口与目录结构见[主说明](../README.md)。

## 账号使用与切换

1.6.0 使用“当前账号持续使用，额度受限时切换”的策略。请求不会轮流分配，也不会为了减少排队而调用其他账号。第一次连接的页面作为当前账号；切换成功后持续使用新账号，旧账号冷却结束或新页面接入都不会抢回请求。

日常只需打开一个账号页面，无需一次登录所有 Google 账号：

1. 在 AI Studio Playground 登录当前账号，安装本地提供的用户脚本，点击一键激活。面板在当前标签页新建对话并发送 Meow，读取页面登录邮箱后自动连接；读不到邮箱时，在“连接设置”中填写主邮箱并确认。
2. 额度受限后，结束当前生成并关闭旧页面，再按需登录或打开另一个账号的 Playground。
3. 在新页面点击一键激活，等面板识别新账号并显示连接成功，然后在酒馆重新发起请求。失败的请求不会在等待手动登录期间自行重放。

可使用同一浏览器中不同 Google 账号位，或不同浏览器配置（各自安装用户脚本，按需打开即可）。新版按确认的邮箱区分账号：不同邮箱复用账号位 0 不会继承彼此冷却；同一邮箱换浏览器或账号位仍保留冷却，同一邮箱同时只能连接一个页面。

1.7.2 从 AI Studio 原生账号按钮读取登录邮箱，并与当次原生请求捕获的会话绑定；不读取聊天正文中的邮箱，也不靠邮箱完成 Google 身份验证。账号按钮或请求上下文变化时断开旧连接，新账号完成激活后重新绑定。读不到或无法唯一确认邮箱时保留手动填写；比较时忽略大小写及两端空格，不自动合并别名。浏览器记住最近 8 个邮箱供手动选择，新页面不直接绑定历史邮箱。单纯本地 WebSocket 断线重连不需要再次激活，正在生成时不能手动修改邮箱。

如果已经有多个就绪页面在线（最多 8 个），其他页面只作为备用。当前账号收到 Google HTTP 429（可能是额度耗尽，也可能是短期频率限制）时，当前模型默认冷却 15 分钟。尚未收到任何上游数据的初始请求可转交备用页面，每个账号最多尝试一次，每次请求最多尝试 8 个账号。全部不可用时返回 429，提示等待冷却、改用其他模型或手动换号，不会无限重试。原页面断开时，在途请求会失败，后续请求可使用其他在线页面。

Google 响应体中的 RPC code 8 同样记录当前模型冷却；由于已经收到上游数据，本次请求保持报错，下次请求才选择可用账号。其他已有上游数据、已完成输入读取或进入续写阶段的请求也不会跨账号重放。连接失败、本地队列已满和其他 HTTP 错误不会触发额度换号；当前账号正在验证实验能力时，聊天等待验证结束。换号保留原请求总时限，调用方取消仍会停止当前执行。

冷却只针对受限模型，其他模型仍可使用。邮箱与未过期的模型冷却写入安装目录的 accounts.json，浏览器重连、后台重启和固定管理器更新均保留；该文件及临时文件已被 Git 忽略，发布包也不包含它们。记录最多 64 个账号，每个账号最多 100 个模型，不保存密码、Cookie、聊天或生成内容。通过 config.json 的 accountCooldownMs 调整冷却时长，单位毫秒，默认 900000。冷却到期只是允许再次尝试，不代表 Google 配额已经恢复。

主面板显示本页完整邮箱，页面活动日志中的账号标签只显示掩码。带本机密钥的 /v1/status 返回完整邮箱、identity: email、accountStrategy: quota-failover、各页面的 active 状态、请求数与模型冷却时间；公开 /health 不包含邮箱，diagnostics.log 不写入邮箱。旧用户脚本仍能以 legacy-slot 身份连接，但无法按邮箱去重或持久化冷却，需更新脚本；旧账号位冷却不会自动迁移到邮箱。离线回归覆盖邮箱绑定、冷却持久化、固定账号、并发排队、额度切换与手动接入，真实 Google 多账号生成仍需实际验证。

本版不内置浏览器，不读取 `.env` 中的 Google 账号密码；登录由你在浏览器中完成，现有 `.env` 可以留在本机且已被 Git 忽略。Playwright 可以复用登录状态，但 [Google 可能阻止自动化浏览器登录](https://support.google.com/accounts/answer/7675428?hl=en)，并不保证减少风控。若日后引入浏览器自动化，优先考虑手动登录一次后复用独立会话、按需启动；[Playwright 的登录状态文件含敏感凭证](https://playwright.dev/docs/auth)，需要作为本地私密文件保存。

Windows / Linux / Android Termux 共用此包，需要 Node.js 22+。默认密钥 `mmdb`，只支持文本聊天。浏览器需支持用户脚本；后端不能代替已登录的 AI Studio 页面。

## PG 自动读取输入（1.5.0）

在新版 MMDB 浏览器面板展开“生成设置”，开启**工具读取输入**。设置自动保存，后续请求立即生效。酒馆沿用原来的 PG 地址和模型，在普通输入框写动作、点发送即可；无需安装 TicketBridge 或其他输入工具扩展，也不需要填写“场景材料”“本轮要求”。已有输入工具扩展应保持关闭，避免重复处理。这个开关不要求酒馆开启 Function Calling。

PG 会先发起一次真实的 `mmdb_read_input` 模型调用，校验返回的请求编号，再将本轮原文作为相应的工具结果提供给第二次生成。上游返回的工具调用 ID、思考签名随对应调用保留。客户端只收到最终正文，中间读取过程不写进酒馆聊天记录。普通模型和抗截断模型均支持。

当前范围是请求中**最后一条 user 消息的文本**，不是全部预设、世界书或历史。若酒馆预设把尾部指令也发送成 user 消息，读取对象就是实际请求里的最后一条 user；PG 无法仅凭兼容接口判断哪一段来自输入框。历史、系统提示及角色上下文在生成阶段保留。图片、附件、客户端自定义工具仍未实现。

新安装默认关闭，可随时关闭恢复原流程。每轮增加一次模型请求及其用量，首个正文通常会更晚到达；读取阶段最多请求 1024 输出 token，不占用正文的输出预算。编号不匹配、未调用读取工具、拒绝、超时或断流会明确报错，不会伪造读取成功。读取与正文两阶段共用整次请求期限，并支持酒馆停止按钮取消。

2026-10-25 在本机实测：普通 Argon 接口约 14 秒完成两次调用；SillyTavern 1.19.0 通过 `pg-gemini-4-argon-抗截断` 普通发送，约 24 秒完成读取及回复，聊天界面收到带指定茶签编号的正文。诊断确认 `inputReadCompleted: true`、`inputReadCalls: 1`，两次尝试均正常结束。验证使用独立的日常茶馆测试角色；未验证规避输入拦截。其他模型、长角色卡及原生跨轮长输出仍需各自验证。

## 反代面板

1.7.0 重新整理了状态、操作和设置：上方显示会话与本地连接状态，生成时显示当前阶段和耗时；下方保留两个独立功能开关。账号邮箱、密钥与复制 API 地址位于“连接设置”。“最近活动”仅保留最近 40 条关键记录，可随时清空。面板移除了实际模型核验提示、请求头和验证入口等技术日志，只显示实际收到的用量计数。

**一键激活 · Meow**：点击后通过 AI Studio 原生按钮在当前标签页新建对话，再发送 `Meow`；已是空白新对话时直接使用。等待会话捕获和页面结束生成后，读取当前登录邮箱并自动连接本地服务。读不到邮箱时保留手动填写。不会自动清除已有草稿；酒馆或 AI Studio 正在生成时拒绝激活；重复点击不会重复发送。新建失败、页面加载中、控件不可用或发送后等待超过 60 秒会显示提示，不自动重发。也可以自行在页面发送任意简短问候完成激活。

**悬浮窗**：点击后把同一个实时面板移到独立窗口，切到酒馆标签页或其他应用仍可查看状态、修改设置。支持 Document Picture-in-Picture 的浏览器使用置顶窗；不支持时打开普通小窗，普通小窗不会自动置顶。置顶请求被拒绝时可点击“改用独立小窗”。关闭小窗或点击“收回面板”会恢复原页面上的面板，开关、日志和输入内容保留。AI Studio 源页面必须保持打开，关闭或刷新源页面会结束该窗口。浏览器能力说明见 [Chrome 官方文档](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)。

**跟随酒馆美化**：底部配色默认选择“跟随酒馆”。同一浏览器配置、同一个脚本管理器中，酒馆页和 AI Studio 页启用同一份 MMDB 脚本后，会自动同步酒馆实际生效的背景、文字、强调色、边框、字体栈、圆角和阴影。换主题后约 1.5 秒内更新，面板与悬浮窗共用最新外观；关闭酒馆后保留最后一次主题。每位用户读取自己的主题，不共享其他人的配色。

更新脚本后需打开或刷新一次酒馆页面。默认覆盖 localhost、127.0.0.1 与常见私网 IPv4 地址的任意端口；使用自定义域名或 IPv6 时，在油猴的脚本设置中为酒馆地址添加“用户匹配”规则，再刷新酒馆。不同浏览器或配置之间不共享用户脚本存储，需要在运行 AI Studio 的同一浏览器中打开酒馆。未读到主题时使用中性默认配色；底部也可切换固定浅色、深色。

同步的是可移植的样式值，不加载整份自定义 CSS，也不复制背景图片、远程字体文件或依赖酒馆 DOM 的装饰。字体会使用该浏览器中可用的同名字体，否则沿字体栈回退。样式通过脚本管理器本地存储传递，不发送到 Google 或本地反代 API。

手机默认显示可拖动的小状态条，点击展开；不支持置顶窗的手机浏览器不能保证切换应用后仍显示面板。标题与小状态条也支持方向键移动，Escape 可收起设置或面板，浅色和深色可在底部切换。

## 便携菜单（1.4.1）

Windows 完整解压后双击 `MMDB.cmd`；Linux / Termux 执行 `bash mmdb.sh`。菜单提供依赖检测、安装 / 修复、本机 / LAN 启动、停止、日志和用户脚本入口。首次选择 1 检测、2 安装项目依赖、3 启动。Windows 缺少 Node.js 时选择 8，由菜单从 nodejs.org 下载并校验官方 LTS 安装器，再由用户完成安装向导。已有依赖先检测，满足版本时不重新下载。

程序、依赖和配置留在解压目录。退出菜单不会停止后台，停止前检查本目录进程及活动请求。详见 [PORTABLE_README.txt](PORTABLE_README.txt)。这次没有新增后端在线更新源；此前 1.4.0 的工具和续写逻辑不变。

## 启动

先完整解压。首次启动安装唯一依赖 ws，需要联网。

| 平台 | 本机酒馆 | 手机连接此设备 |
| --- | --- | --- |
| Windows | 双击 Start.cmd | 双击 Start-LAN.cmd |
| Linux | bash start.sh | bash start-lan.sh |
| Termux | bash start.sh | bash start-lan.sh |

Linux 先安装 Node.js 22+ 和 npm；Termux 执行 `pkg install nodejs-lts npm`。Termux 将项目放在其主目录（例如 ~/mmdb-pg），避免在 Android 共享存储里安装 node_modules。手机浏览器必须支持用户脚本，并保持 AI Studio 页面运行；系统后台冻结会影响生成。

启动后保持窗口运行，Ctrl+C 停止。Windows 也可用 Stop.cmd；新版核心和 LAN 入口属于同一进程，Stop-LAN.cmd 同样停止整个服务。不要重复启动两种模式；改用 LAN 模式前先停止当前服务。

## 安装浏览器脚本

打开 `http://127.0.0.1:8765/local-pg.user.js?v=1.7.1`，将 **MMDB 本地桥**原位更新到 **1.7.1**，然后刷新 AI Studio。新面板与一键激活需要新版用户脚本。

进入 AI Studio Playground，点击一键激活，确认面板显示本地已连接、Google 已就绪。保持输入框没有未发送的草稿。

酒馆使用聊天补全 → 自定义兼容 OpenAI：

- 本机 Base URL：`http://127.0.0.1:8765/v1`
- 密钥：`mmdb`
- 普通模型：如 `pg-gemini-4-argon`，支持流式显示。
- 抗截断模型：如 `pg-gemini-4-argon-抗截断`，通过正文工具交付，按完整工具参数返回；实测正文一次显示。

普通与抗截断使用同一登录账号。工具模式不是更高额度，也不能保证消除所有截断。没有实际调用正文工具时明确报错，不静默切回普通输出。上游断流、额度和拒绝保留为错误。酒馆点停止会取消请求。

## 局域网

LAN 启动方式会同时启动本机核心和手机 API 网关。唯一可识别的私网 IPv4 会自动生成 lan-config.json；多网卡、VPN 或地址变化时，参考 lan-config.example.json 手工修改 address 与 allowedCIDR。

手机填启动窗口显示的 `http://电脑局域网IP:8766/v1`，密钥与电脑一致。电脑与手机应在可互通网络中；如系统防火墙提示，允许家庭私网访问。LAN 只提供生成 API，限制配置网段并验证密钥。不要把此入口映射到公网。

## 配置与等待

首次生成 config.json，已有配置保留。默认值：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| port | 8765 | 本机端口 |
| apiKey | mmdb | 个人密钥 |
| timeoutMs | 180000 | 普通模型首个有效内容／已有正文后的数据空闲上限，毫秒 |
| toolFirstByteTimeoutMs | 600000 | 工具模式首个有效工具正文等待上限，毫秒；JSON 前缀和思考帧不缩短此预算 |
| queueTimeoutMs | 120000 | 新版浏览器执行器开始工作前的排队上限，毫秒 |
| maxRequestMs | 1800000 | 整次请求总时长上限，毫秒；含排队、重试和所有续写 |
| streamKeepAliveMs | 15000 | SSE 注释／非流式 JSON 空白保活间隔，毫秒 |
| maxContinuations | 2 | 最多额外续写次数，可设 0–5；提示词续写需明确 MAX_TOKENS、已有正文且未耗尽请求输出预算 |
| accountCooldownMs | 900000 | Google HTTP 429 或 RPC code 8 后，当前账号对应模型的本地冷却时长，毫秒；100–86400000 |
| nativeContinuation | false | PG 原生续写；仅对具备已确认能力的抗截断模型启用 |
| inputRead | false | 先通过一次真实工具调用读取最后一条 user 文本，再生成正文；每轮增加一次模型请求 |
| models | 内置模型列表 | 根据账号实际权限修改 |

SSE 注释没有正文，不会延长上游等待期限。非流式响应每隔同样的时间发送合法 JSON 空白，最后仍是一个完整 JSON 对象；保活不含正文。保活发出后 HTTP 状态已为 200，晚到错误通过 JSON error 对象返回；首个保活之前的错误仍使用实际 HTTP 状态码。未实际收到上游数据时，本地代码无法提前显示正文。

## 计时和诊断

面板“请求耗时”包含执行器排队，完成时使用后台从收到该次生成请求起计算的总耗时。它不包含酒馆发起请求之前的预处理，也不等于酒馆的“思考”标签或页面渲染耗时。酒馆使用近似分钟显示时，152 秒可能显示为“3 分钟”；可悬停其标签查看秒数（取决于酒馆版本）。

`GET /v1/status` 需要 `Authorization: Bearer mmdb`，包含活动请求及最近 50 次调用的阶段、数据块数与相对耗时。firstClientTextMs 表示后台第一次调用正文写出，不是酒馆收到或显示的时刻。诊断仅保存元数据到 diagnostics.log，不保存提示词、正文、Cookie 或令牌。

工具读取增加 `inputReadEnabled`、`inputReadCompleted`、`inputReadCalls`，尝试记录用 `reason: input-read` 区分读取阶段。用量包含读取请求；缺失的上游计数仍保持未知。设置接口 `POST /v1/experiments` 接受局部更新，例如 `{"inputRead":true}`，不会覆盖另一项功能开关。

## 升级

先结束生成、停止旧服务。将新版解压到新文件夹，按需复制自己的 config.json 和 lan-config.json，再启动。安装新版用户脚本并刷新 AI Studio、点击一键激活。旧文件夹确认不再需要后自行删除。分发包不含你的配置、密钥历史、日志、PID、node_modules 或聊天数据。

## 生成设置

**工具读取输入**和**原生续写**已作为常规功能提供，保留独立开关，默认关闭，沿用已有 config.json 的值。设置自动保存，后续请求立即生效；生成、激活或能力探测期间锁定，保存失败则保留原值并显示原因。

原生续写只作用于当前账号能力目录声明支持的抗截断模型。不支持时沿用提示词续写。工具读取输入适用于普通与抗截断模型，每轮增加一次调用，范围与用量见前文。为兼容已安装客户端，设置接口仍保留 `/v1/experiments` 和原有 WebSocket 消息名。

历史探测和验证范围留在 [EXPERIMENTS.md](EXPERIMENTS.md)，不再放入日常面板。功能转正不代表新的模型或长输出已自动获得实测覆盖。

## 响应前连接失败的恢复

仅提示词续写的抗截断模式在收到任何响应字节之前发生连接错误（包括已有响应头但读不到数据），会重新生成会话验证并自动重试一次。同一个客户端请求最多一次恢复，包括后续 MAX_TOKENS 轮次；整体等待上限不因重试而重置。已收到任何响应字节后的断流、任何 HTTP 错误、额度、权限、内容拒绝及主动取消都不重试。原生续写模式不重试传输失败，避免重复消费状态不明的续写凭据。

断开时无法确认 Google 是否已开始生成，因此重试可能额外消耗一次调用；它不能保证网络不掉线。面板会明确显示重试事件，诊断 networkRetries 记录次数。普通模型不启用这层恢复。

## 用户脚本自动更新

1.2.0 起提供本机 @updateURL 与 @downloadURL。手动安装一次此版本后，在油猴中开启该脚本的更新检查。以后先升级本地后台文件，保持后台运行，油猴便可按其检查周期从本机获取新版本；也可在油猴中手动检查更新。安装后刷新 AI Studio 使新脚本生效。更新检查时间和权限取决于脚本管理器设置，无法保证立即自动安装。

这个机制不会自动下载新的后端启动包，也不会从旧的后台目录获得尚未升级的代码。旧版脚本还没有这些更新声明，需要先手动安装一次。

## 性能诊断与精简策略（1.2.0）

本版记录实际发送的 generation 参数、toolPromptStyle、每次请求尝试的阶段时间和上游用量。usage 中缺失的 token 字段表示未知，显式 0 才是报告为零。usageComplete 表示能否完整汇总输入、输出、思考和总 token 计数；失败尝试的未报告用量不会被假装为零。attempts 中分别保留首次尝试、网络恢复和续写的数据，单次使用上游累计计数的最后值，不重复相加每个响应帧。HTTP 兼容接口与诊断共用同一份记录：无法得到完整 OpenAI 用量统计时省略 usage；诊断仍保留上游明确报告的部分计数。原生续写的输入不重复相加，其总量还依赖前轮工具 token 计数，缺失时保持未知。

面板区分响应头、响应数据和正文到达；这些时刻都不能精确表示 Google 内部开始或结束思考的时间。

精简交付要求已作为可选方案实现：在 config.json 中添加 `"toolPromptStyle": "compact"` 后重启后台即可启用；恢复 `"legacy"` 可回退。两种策略的模型、温度、topP、输出上限和思考设置完全一致，精简版只减少重复交付指令，仍保留真正的工具声明、user 结尾和严格工具结果验证。模型列表不增加第三类。

默认保持 legacy：精简策略通过离线结构和回归检查，尚未验证实际模型的工具调用成功率与提速。没有在发布时偷偷降低思考强度或截短输出。实测前不能承诺把 262 秒降回 116 秒。网页 Run settings 不会自动同步到反代，未显式发送的生成参数在诊断中记为 provider-default；thinkingConfigSent=false 表示没有发送思考配置，不表示模型没有思考。

在项目目录运行 `node tools/performance-report.mjs` 可只读汇总现有诊断，无需生成请求。仅统计有明确配置、没有重试／续写的成功记录，按普通／工具策略分组显示中位数和可用的 token 统计；未知计数显示 null，旧记录缺少配置会被排除。这些自然使用记录不保证输入相同，不能冒充受控实验。

## 长时间非流式请求（1.2.1）

反代给非流式请求发送 JSON 空白保活。酒馆原本会把整篇 JSON 缓冲完再回复浏览器，因此使用酒馆时还需在酒馆所在设备运行一次：

```sh
node tools/install-st-keepalive.mjs "你的SillyTavern目录"
```

然后重启酒馆。Windows、Linux、Termux 都可用同一命令；手机酒馆装在手机上时，补丁也要应用在手机酒馆目录。命令会检查生成入口的结构，不匹配时拒绝修改，重复运行不会叠加补丁。酒馆更新后若覆盖了补丁，重新运行即可。只转发带 MMDB 标记的自定义 pg- 模型非流式 JSON，不修改预设、聊天、普通流式显示或其他提供商的行为。

这段保活让本地 HTTP 链路不再长时间完全静默，无法取消客户端自己的固定总时长上限，也无法向 Google 的响应连接注入数据。如果依然在固定时间断开，需要结合该客户端的限制继续定位。诊断 clientKeepAlives / lastKeepAliveMs 记录保活发送情况；client_disconnected 表示调用方断开，不能单凭该状态认定是超时。

Google 连接失败只在没有收到任何数据时允许已有的一次恢复；读到部分内容后断流会明确报 upstream_stream_disconnected，不重放已收到的内容、不伪装完成，也不无限重试。代理或 Google 主动断线仍可能失败；本地保活不能保证修复这一段网络。

## 手机悬浮条挡住发送键（1.2.2）

## 交付正确性与原生续写（1.3.0）

LAN 网关现在保留 MMDB 的 JSON 空白保活标记，使电脑核心 → LAN → 酒馆后端 → 客户端的非流式保活完整传递。酒馆端仍需安装上文的保活适配。工具生成错误、未知完成枚举、空白工具正文、工具与普通正文混合输出都会明确失败；流式已交付的部分内容不能收回，但不会追加成功结束信号。收到 finish 帧后仍等待整个上游传输正常结束，并接收尾随的 usage 帧。

架构仍是酒馆 → 可选 LAN 入口 → 本机 Node 核心 → 浏览器执行器 → PG。核心新增独立的 `deadlines.mjs` 和 `capabilities.mjs`；续写由 `continuation.mjs` 负责，用量由 `metrics.mjs` 统一汇总。新版浏览器协议区分连接、逻辑请求、轮次请求和网络尝试，忽略迟到的旧尝试数据。排队取消不会继续执行；账号请求上下文变化会取消旧任务并清空旧目录。旧脚本可以继续使用基础交付，但不启用原生续写，也没有新版独立排队计时，应与后台一起升级。

浏览器会通过当前页面捕获到的实际请求头查询 ListModels，不伪造会员或账号信息，不读取聊天内容。目录只保留在当前连接内，定期刷新，10 分钟过期；`/v1/status` 的 catalog 显示状态与已配置模型的能力。模型列表仍由 config.json 的 models 控制，目录不会自动暴露所有模型。

原生续写默认关闭。可在 config.json 中添加 `"nativeContinuation": true` 后重启后台；同时需要 1.3.0 用户脚本，以及新鲜目录中同时声明函数工具、output_continuation 和有效 token 上限的模型。实际使用方式记录在诊断 `continuationMode` 中：native / prompt / none。开关开启但能力不满足时，继续使用原有提示词续写；一旦已经进入原生流程，协议错误不会静默切换为提示词重放。

原生流程保持原始 contents、system、工具声明和 WAA binding，逐轮生成新的 proof，只追加 PG 返回的 continuation token；每轮累计输出上限增加 32768，受 max_tokens、maxContinuations 和 maxRequestMs 共同约束。明确 CONTINUATION，或带本帧 token 且仍有输出预算的 MAX_TOKENS，才会触发下一轮。缺失／重复 token 或必须续写但预算耗尽时明确报错；正常 MAX_TOKENS 没有可用续写条件时仍报告 length。凭据不会写进诊断日志或客户端响应。

**当时的验证边界（1.3.0）：** 已覆盖离线协议、执行器状态、取消、超时、尾帧用量和 LAN 保活回归。当时环境没有运行 MMDB 或打开 AI Studio，未完成真实模型的原生续写及工具参数跨轮行为验证；1.4.0 的最新实测范围见 EXPERIMENTS.md，当时保留为实验选项；1.7.0 已转为常规开关。现阶段仍按完整 protobuf 工具参数解码，没有假设上游提供可逐字符追加的 JSON 参数，也不承诺原生模式可以消除所有截断。

## 续写接缝、输出预算与工具校验（1.3.1）

提示词续写轮的正文先暂存到该轮上游传输正常结束，再检查与已有正文的接缝。至少 32 个 UTF-16 单元、包含至少 16 个字母或数字的精确重叠才会移除；通常比较末尾 8192 个单元，也识别整篇原文的完整重放。短句、标点、空行和代码围栏不做模糊去重，正文不会被统一空白或改写。若整轮只重复上一轮／已有正文，或移除接缝后没有新增正文，返回 `continuation_no_progress`，停止额外请求。流式已显示的前轮内容保留，重复的续写正文不会再发出，也不会追加成功结束信号。首轮和原生续写的交付时机保持原有行为。

**输出上限语义调整：** 提示词续写现在将显式 `max_completion_tokens`、`max_tokens` 或 Gemini `maxOutputTokens` 视为整次答复的预算，后续轮次扣除各次尝试已报告的输出与思考 token，不再每轮重置。`max_completion_tokens` 优先于 `max_tokens`。预算耗尽、或缺少准确计数无法确定剩余额度时，不再自动续写，保留 `length` 结束原因；未设置输出上限时仍使用上游默认值，并受续写次数和总时长限制。需要长答复时，应在酒馆设置足够的输出上限。预算不会用字符数估算 token，也不能约束上游误报用量或响应前网络重试的未知消耗。

正文工具允许先到名称、后到参数；带调用 ID 时，同一答复内的 ID 必须一致。同一帧多次调用、调用 ID 切换、完成后继续调用，以及尚未验证的参数扩展均明确失败，不把不同调用或未解析参数拼成正文。原生续写仍默认关闭，没有尝试向 PG 注入未经验证的 `ANY` 或 `streamFunctionCallArguments` 字段。

诊断新增 `continuationOverlapChars`（移除的重叠长度）、`continuationRemainingTokens`（已知的剩余预算）和 `continuationStop`（`output_budget` / `unknown_usage` / `max_rounds`），不保存正文、调用 ID 或签名。本版覆盖接缝、重放、预算、工具标识及断流的离线模拟回归；未据此宣称真实 PG 的工具增量参数或长输出能力已经验证。

升级后重启本地后台，更新用户脚本并刷新 AI Studio。现有配置无需增加字段。
